Leçon 0.4 · environ 2 h 30

VS Code et Claude Code : bien travailler avec l'IA

Objectif : utiliser VS Code pour lire, écrire et enregistrer du code, et utiliser Claude Code comme un coach : savoir quoi lui demander, comment, et vérifier ce qu'il fait.

Partie 1 — VS Code, ton atelier

Notion 1 — Ouvrir ton projet et t'y retrouver

C'est quoi ?

VS Code est un éditeur de code : un traitement de texte spécialisé pour le code, gratuit, déjà installé sur ton PC. Contrairement à Word, il n'ajoute aucune mise en forme cachée : ce que tu tapes est exactement ce qui est enregistré.

Comment ouvrir ton projet

cd ~/Documents/formation-ia
code .        # ouvre VS Code sur le dossier actuel (le point = « ici »)
code journal.md   # ouvre un fichier précis (le crée s'il n'existe pas)

Sans terminal : dans VS Code, menu Fichier › Ouvrir le dossier…, puis choisis formation-ia.

Toujours ouvrir le dossier entier, pas un fichier seul : VS Code affiche alors toute l'arborescence et Git fonctionne.

Les 4 zones

Éditeur (au centre)Là où tu écris. Un onglet par fichier ouvert.

Notion 2 — Le terminal Git Bash dans VS Code

Comment le régler (une seule fois)

  1. Ouvre le terminal : menu Terminal › Nouveau terminal.
  2. Clique sur la flèche ˅ à côté du +, en haut à droite du terminal.
  3. Choisis Sélectionner le profil par défaut, puis Git Bash.
  4. Ferme le terminal (icône 🗑️) et rouvre-le : l'invite finit maintenant par $.

Pourquoi c'est pratique

  • Le terminal est déjà dans ton projet : pas besoin de cd.
  • Ctrl+V colle normalement, et Ctrl+C copie quand du texte est sélectionné.
  • Le code et le terminal sont dans la même fenêtre.

Notion 3 — Écrire, enregistrer, voir le résultat

Enregistrer : le réflexe n°1

Une modification non enregistrée n'existe pas pour le navigateur, ni pour Git, ni pour Claude. Un rond ● sur l'onglet veut dire « pas enregistré ». Appuie sur Ctrl+S : le rond devient une croix ✕.

Pour ne plus jamais oublier : menu Fichier › Enregistrement automatique.

Les raccourcis qui font gagner du temps

RaccourciActionQuand l'utiliser

Ctrl+POuvrir un fichier en tapant son nomPlus rapide que de chercher dans l'explorateur
Ctrl+FChercher dans le fichierTrouver un mot, une balise
Ctrl+GAller à une ligneQuand Claude ou une erreur te donne un numéro de ligne

Voir ta page web

  • Le plus simple : double-clique sur le fichier .html dans l'Explorateur Windows. Après chaque modification : Ctrl+S dans VS Code, puis F5 dans le navigateur.
  • Le plus confortable : installe l'extension Live Preview (Microsoft) via l'onglet Extensions (Ctrl+Shift+X). Ouvre ton fichier HTML et clique sur l'icône d'aperçu en haut à droite : la page s'affiche à côté du code et se met à jour à chaque enregistrement.

Erreurs fréquentes

  • « J'ai modifié mais rien ne change » → le fichier n'est pas enregistré (rond ●), ou tu n'as pas rafraîchi la page (F5).
  • Ouvrir un .md par double-clic dans Windows : il ne sait pas avec quoi l'ouvrir. Utilise code fichier.md, ou clic droit › Ouvrir avec › Visual Studio Code.

Notion 4 — Git avec des boutons : le Contrôle de source

Comment l'utiliser

  1. Ouvre l'onglet Contrôle de source (Ctrl+Shift+G). Les fichiers modifiés sont listés, avec un M (modifié) ou un U (nouveau).
  2. Clique sur un fichier : VS Code montre l'avant (à gauche) et l'après (à droite). C'est git diff en couleurs.
  3. Le + à côté d'un fichier = git add.
  4. Écris le message dans la case du haut, puis clique sur Valider (Commit) = git commit -m.
  5. Le bouton Synchroniser = git pull puis git push.

Terminal ou boutons ?

Les deux font exactement la même chose. Apprends d'abord les commandes (pour comprendre), puis utilise les boutons quand tu veux aller plus vite.

Partie 2 — Claude Code, ton coach

Notion 5 — Comment fonctionne Claude Code

C'est quoi ?

Claude Code est un assistant IA qui travaille directement dans ton dossier : il lit tes fichiers, peut les modifier et lancer des commandes. Il te demande la permission pour les actions importantes.

Claude Code ou Claude Chat ?

Claude CodeClaude Chat
Voit tes fichiers ?✅ Oui, directement❌ Seulement ceux que tu colles ou ajoutes
Peut modifier ton projet ?✅ Oui, avec ta permission❌ Non
À utiliser pour…écrire et relire du code, lancer des commandes, faire avancer le siteréviser un concept, faire des fiches, réfléchir à une idée

Ce qu'il retient d'une conversation à l'autre

Rien, sauf ce qui est écrit dans des fichiers. C'est pour ça que ton projet a :

FichierRôleQuand Claude le lit
CLAUDE.mdLes règles permanentes : qui tu es, le mode coach, les conventionsAutomatiquement, à chaque nouvelle conversation
PROGRESSION.mdOù tu en es, ce que tu sais faireAu début de chaque session (c'est une règle de CLAUDE.md)

Pour qu'il retienne quelque chose, demande-le : « Ajoute dans CLAUDE.md que je préfère des exemples liés au e-commerce. » (La commande /init crée un CLAUDE.md dans un projet qui n'en a pas : tu n'en as pas besoin ici.)

Le mode plan

Pour une grosse tâche, active le mode plan : Claude réfléchit et te propose un plan sans rien modifier. Tu le relis, tu le corriges, puis tu valides. C'est comme ça qu'on a créé cette formation.

Quand l'utiliser ? Dès que la tâche touche plusieurs fichiers, ou que tu n'es pas sûr de la méthode. Pour une petite question : inutile.

Notion 6 — Bien formuler une demande (un prompt)

La formule en 4 ingrédients

IngrédientLa question à te poserExemple
ContexteQui suis-je, où j'en suis ?« Je suis débutant, leçon 1.1 sur le HTML. »
ObjectifQu'est-ce que je veux obtenir, précisément ?« Je veux comprendre à quoi sert <main>. »
ContraintesSous quelle forme je veux la réponse ?« En 3 phrases, avec un exemple, sans me donner tout le code. »
Critère de réussiteComment je saurai que c'est bon ?« Je dois pouvoir l'expliquer ensuite à un ami. »

Exemples avant / après

❌ Vague✅ Précis
« Fais-moi une page. » « Je suis à la leçon 1.1. Je veux créer exercices/module-1-1/a-propos.html qui me présente. Ne l'écris pas pour moi : donne-moi la liste des balises dont j'aurai besoin, dans l'ordre. »
« Ça marche pas. » « Dans index.html, ma nouvelle section ne s'affiche pas. Voici l'erreur / ce que je vois : … Donne-moi un indice, pas la solution. »
« Comment utiliser l'IA au maximum ? » « Je suis débutant et j'apprends à coder avec Claude Code. Donne-moi les 5 erreurs les plus courantes quand on écrit un prompt, avec un exemple mauvais / bon pour chacune. »

Quand tu bloques : la demande parfaite

Donne toujours le fichier concerné, ce que tu as essayé, et le message d'erreur exact (copié-collé). Avec ça, Claude trouve en quelques secondes.

Notion 7 — Rester le chef : relire et sécuriser

  • Lis toujours ce que Claude propose de modifier ou d'exécuter avant d'accepter.
  • Ne garde jamais un code que tu ne comprends pas. Demande : « Explique-moi cette ligne avec un exemple de la vie quotidienne. »
  • Ne colle jamais un mot de passe, une clé API ou une donnée bancaire dans une conversation.
  • Fais un commit avant de demander une grosse modification : si le résultat ne te plaît pas, tu peux revenir en arrière.

Exercices

Exercice 1 — Prendre VS Code en main

Ce qu'on attend de toi : changer la couleur principale du site, la voir s'afficher, et repérer ta modification dans le Contrôle de source.

  1. Ouvre le projet avec code ..
  2. Ouvre site/css/style.css (Ctrl+P, tape style) et lis la section 1 « Variables ».
  3. Change la valeur de --accent, par exemple en #e11d48 (rouge framboise). Enregistre.
  4. Ouvre site/index.html dans ton navigateur et rafraîchis (F5). Les boutons et liens ont-ils changé de couleur ?
  5. Ouvre le Contrôle de source et clique sur style.css pour voir l'avant / après.

Comment vérifier que c'est réussi : le bouton « Continuer » de l'accueil a ta nouvelle couleur.

Indice : rien ne change ?

Ton ordinateur est peut-être en mode sombre. --accent est défini une 2e fois, plus bas, dans le bloc @media (prefers-color-scheme: dark). C'est cette valeur-là qui gagne en mode sombre.

Correction (ouvre-la après avoir essayé) 
/* Section 1, dans :root (mode clair) */
--accent: #e11d48;

/* Plus bas, dans @media (prefers-color-scheme: dark) (mode sombre) */
--accent: #fb7185;   /* une version plus claire, lisible sur fond noir */

Pourquoi deux valeurs ? Le bloc @media (prefers-color-scheme: dark) ne s'applique que si ton ordinateur est en mode sombre, et il vient après :root : en CSS, quand deux règles visent la même chose, la dernière gagne. C'est la « cascade » (le C de CSS), qu'on verra en leçon 1.3.

Ensuite : git add site/css/style.css → git commit -m "Change la couleur d'accent du site en rouge framboise" → git push.

Exercice 2 — Demander une explication

Ce qu'on attend de toi : choisir une ligne de site/js/main.js que tu ne comprends pas, et obtenir de Claude une explication que tu peux redire avec tes mots.

  1. Ouvre site/js/main.js.
  2. Choisis une ligne de code (pas un commentaire) qui te paraît mystérieuse.
  3. Écris à Claude Code une demande avec les 4 ingrédients (notion 6).
  4. Résume l'explication en une phrase dans ton journal.

Comment vérifier que c'est réussi : tu peux expliquer la ligne à voix haute sans relire la réponse de Claude.

Correction : exemple de demande et de réponse

Demande : « Je suis débutant, leçon 0.4 (contexte). Dans site/js/main.js, je ne comprends pas la ligne const liensMenu = document.querySelectorAll(".nav a"); (objectif). Explique-la en 3 phrases avec un exemple de la vie quotidienne, sans jargon (contraintes). »

Résumé possible : « Cette ligne demande au navigateur de trouver tous les liens du menu, comme si je demandais "donne-moi tous les livres rangés sur l'étagère Menu", et elle les range dans une boîte nommée liensMenu pour les utiliser ensuite. »

Exercice 3 — Écrire 3 bonnes demandes

Ce qu'on attend de toi : un fichier exercices/module-0-4/mes-prompts.md avec 3 demandes que tu pourrais faire à Claude Code pendant la leçon 1.1 (HTML). Chacune contient les 4 ingrédients, et suit ce modèle :

## Demande 1
**Contexte :** …
**Objectif :** …
**Contraintes :** …
**Critère de réussite :** …
  1. Jette un œil à la leçon 1.1 pour savoir de quoi elle parle (balises, squelette, page « à propos »).
  2. Crée le dossier exercices/module-0-4, puis ouvre le fichier avec code exercices/module-0-4/mes-prompts.md.
  3. Écris tes 3 demandes avec le modèle. Enregistre.
  4. Demande à Claude : « Note mes 3 prompts sur 10 et propose une version améliorée de chacun. »
  5. Commit.

Comment vérifier que c'est réussi : chaque demande parle du HTML, et chacune a ses 4 lignes remplies.

Indice : des idées de sujets
  • Comprendre une balise (par exemple la différence entre <section> et <article>).
  • Ta page ne s'affiche pas comme prévu.
  • Demander une relecture de ta page « à propos ».
Correction : 3 exemples notés 9/10 
## Demande 1
**Contexte :** Je suis débutant complet, leçon 1.1 de ma formation HTML.
**Objectif :** Comprendre la différence entre <section> et <article>.
**Contraintes :** Explique en 4 phrases maximum, avec un exemple tiré d'un site de journal en ligne.
**Critère de réussite :** Je dois savoir laquelle utiliser pour une leçon de mon site.

## Demande 2
**Contexte :** Leçon 1.1, j'ai écrit exercices/module-1-1/a-propos.html.
**Objectif :** Mon pied de page ne s'affiche pas en bas de la page.
**Contraintes :** Ne corrige pas le fichier toi-même. Donne-moi un indice sur la ligne à regarder.
**Critère de réussite :** Je trouve et corrige l'erreur moi-même.

## Demande 3
**Contexte :** J'ai fini l'exercice 1 de la leçon 1.1.
**Objectif :** Relis exercices/module-1-1/a-propos.html.
**Contraintes :** Dis-moi d'abord ce qui est bien, puis maximum 3 choses à améliorer, expliquées simplement.
**Critère de réussite :** Une note sur 10 et je sais quoi corriger en priorité.

Ce qui les rend bonnes : le fichier précis est nommé, le format de réponse est imposé (nombre de phrases, indice plutôt que solution), et on sait quand c'est réussi. Il manque juste le dixième point : préciser ce que tu as déjà essayé.

Questions pour vérifier que tu as compris

1. L'onglet de ton fichier affiche un rond ●. Qu'est-ce que ça veut dire, et que fais-tu ?

Réponse

Le fichier n'est pas enregistré. Tu appuies sur Ctrl+S. Tant que c'est un rond, ni le navigateur, ni Git, ni Claude ne voient ta modification.

2. Tu ouvres une nouvelle conversation avec Claude Code demain. Comment sait-il où tu en es ?

Réponse

Il lit automatiquement CLAUDE.md, qui lui demande de lire PROGRESSION.md. Il ne se souvient pas de la conversation précédente : seuls les fichiers comptent.

3. Quels sont les 4 ingrédients d'une bonne demande ?

Réponse

Le contexte, l'objectif, les contraintes et le critère de réussite.

Checklist

  • J'ouvre mon projet dans VS Code et j'utilise son terminal Git Bash.
  • J'enregistre toujours (Ctrl+S) et je reconnais le rond ●.
  • Je vois ma page dans le navigateur et je la rafraîchis.
  • Je sais lire le Contrôle de source.
  • Je sais à quoi servent CLAUDE.md, PROGRESSION.md et le mode plan.
  • J'écris des demandes avec contexte, objectif, contraintes et critère de réussite.
  • Je relis toujours ce que Claude propose avant d'accepter.

Journal et commit

Entrée dans journal.md, puis add → commit → push. Essaie de le faire avec les boutons du Contrôle de source.
