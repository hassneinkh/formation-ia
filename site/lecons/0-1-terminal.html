Leçon 0.1 · environ 2 h

Le terminal : piloter ton ordinateur au clavier

Objectif : à la fin de cette leçon, tu sais ouvrir le bon terminal, savoir où tu te trouves, te déplacer dans tes dossiers, créer, renommer et supprimer des dossiers et des fichiers, et écrire dedans. Uniquement au clavier.

Pourquoi apprendre le terminal ?

Le terminal est une fenêtre où tu écris des ordres à ton ordinateur au lieu de cliquer. Chaque ordre s'appelle une commande. Tous les outils de développeur s'utilisent ainsi : Git, Node.js, Next.js, Expo… Et quand Claude Code travaille pour toi, il tape lui aussi des commandes dans un terminal. Comprendre le terminal, c'est comprendre ce que fait l'IA à ta place.

Notion 1 — Le bon terminal : Git Bash

C'est quoi ?

Windows contient plusieurs terminaux, qui ne parlent pas la même « langue » :

TerminalSon invite (le début de la ligne)Comprend les commandes de la formation ?
Invite de commandes (cmd)C:\Users\hsnyt>❌ Non
PowerShellPS C:\Users\hsnyt>⚠️ En partie
Git Bashhsnyt@PC MINGW64 ~ puis $✅ Oui

On utilise Git Bash (installé avec Git) : ses commandes sont les mêmes que sur Mac et Linux, donc ce que tu apprends ici marche partout.

Comment l'ouvrir ?

  • Seul : touche Windows, tape Git Bash, puis Entrée.
  • Dans VS Code (leçon 0.4) : menu Terminal › Nouveau terminal, flèche ˅ à côté du +, puis Git Bash.

Comment savoir que tu es au bon endroit ?

La dernière ligne se termine par un $. C'est l'invite : le terminal attend ta commande. Tu tapes la commande après le $ (sans retaper le $), puis tu appuies sur Entrée.

Copier-coller dans Git Bash

ActionComment faire
CollerClic droit › Paste, ou Shift + Inser
CopierSélectionne le texte à la souris : c'est copié automatiquement

Erreurs fréquentes

  • 'touch' n'est pas reconnu en tant que commande interne… → tu es dans l'Invite de commandes (cmd), pas dans Git Bash. Ouvre Git Bash.
  • Ctrl+C ne copie pas : dans un terminal, il arrête la commande en cours. Et Ctrl+V ne colle pas dans Git Bash.

Notion 2 — Les chemins : l'adresse d'un dossier

C'est quoi ?

Tes dossiers sont rangés comme des boîtes dans des boîtes. Un chemin, c'est l'adresse d'un dossier ou d'un fichier : la liste des boîtes à ouvrir pour y arriver, séparées par des /.

/c/Users/hsnyt/Documents/formation-ia/site/index.html
  ↑ disque C › Users › hsnyt › Documents › formation-ia › site › le fichier index.html

Les raccourcis à connaître

SymboleSignifieExemple
~Ton dossier personnel (/c/Users/hsnyt), « la maison »~/Documents
.Le dossier où tu es maintenant, « ici »code . (ouvre VS Code ici)
..Le dossier parent, celui juste au-dessuscd .. (remonte d'un niveau)

Chemin relatif ou absolu ?

  • Absolu : l'adresse complète, qui marche d'où que tu sois. Exemple : ~/Documents/formation-ia.
  • Relatif : l'adresse à partir de là où tu es. Si tu es déjà dans formation-ia, tu écris juste site.

Quand utiliser quoi ? Le relatif est plus court quand la cible est proche. L'absolu est plus sûr quand tu ne sais plus où tu es.

Erreurs fréquentes

  • No such file or directory → le chemin est faux, ou tu n'es pas dans le dossier que tu crois. Tape pwd pour vérifier où tu es.
  • Écrire \ (le style Windows) au lieu de / : dans Git Bash, on utilise toujours /.

Notion 3 — Se repérer et se déplacer : pwd, ls, cd

Comment l'écrire

CommandeCe qu'elle faitQuand l'utiliser
pwdAffiche le chemin du dossier où tu es (print working directory)Dès que tu as un doute sur l'endroit où tu es
lsListe ce que contient le dossier (list)Pour voir les noms exacts avant de taper une commande
ls -laListe en détail, y compris les éléments cachésPour savoir si c'est un dossier (ligne qui commence par d) ou un fichier (-)
cd nomEntre dans le dossier « nom » (change directory)Pour te placer là où tu vas travailler
cd ..Remonte d'un niveauPour revenir au dossier parent
cd ~Revient à ton dossier personnelQuand tu es perdu : on repart de la maison

Exemple complet

# Où suis-je ?
pwd
# → /c/Users/hsnyt

# Aller dans le projet (chemin relatif depuis la maison)
cd Documents/formation-ia

# Qu'y a-t-il ici ?
ls
# → CLAUDE.md  PROGRESSION.md  README.md  exercices  journal.md  projets  site

# Entrer dans site, regarder, puis remonter
cd site
ls
cd ..

Deux super-pouvoirs à utiliser tout le temps :

  • Tab : tape le début d'un nom (cd Docu) puis Tab, et le terminal complète tout seul. Moins de fautes de frappe !
  • Flèche du haut : rappelle les commandes précédentes, pour ne pas tout retaper.

Erreurs fréquentes

  • cd.. sans espace → il faut un espace entre la commande et ce qui suit : cd ..
  • Les espaces dans les noms : cd Mes projets ne marche pas, car le terminal croit que ce sont deux choses. Il faut des guillemets : cd "Mes projets". C'est pour ça que les développeurs nomment tout avec-des-tirets.

Notion 4 — Créer : mkdir (dossier) et touch (fichier)

C'est quoi ?

mkdir (make directory) crée un dossier. touch crée un fichier vide.

Comment l'écrire

mkdir mon-dossier                  # crée le dossier "mon-dossier" ici
mkdir exercices/module-0-1         # crée "module-0-1" DANS le dossier "exercices" (qui doit déjà exister)
mkdir -p a/b/c                     # -p crée aussi les dossiers parents s'ils n'existent pas
touch notes.txt                    # crée le fichier vide "notes.txt" ici
touch exercices/module-0-1/notes.txt   # crée le fichier dans ce dossier

Quand utiliser lequel ?

Tu veux…Utilise
une boîte pour ranger des chosesmkdir
un fichier dans lequel écrire (texte, code, notes)touch

Erreurs fréquentes

  • mkdir commandes.txt → crée un dossier qui s'appelle « commandes.txt », même avec le .txt. Tu ne pourras pas écrire dedans (erreur Is a directory). Pour un fichier, c'est touch.
  • Un nom légèrement différent : module-04 ou modules-01 au lieu de module-0-1. Pour l'ordinateur, un seul caractère différent = un autre dossier.

Notion 5 — Écrire et lire : echo, >, >>, cat

C'est quoi ?

  • echo "texte" affiche un texte à l'écran.
  • Avec une flèche, ce texte part dans un fichier au lieu de l'écran.
  • cat fichier affiche le contenu d'un fichier.

Comment l'écrire

echo "Bonjour"                     # affiche Bonjour à l'écran
echo "Bonjour" > salut.txt         # >  : ÉCRASE le fichier et met "Bonjour" dedans (le crée s'il n'existe pas)
echo "Ça va ?" >> salut.txt        # >> : AJOUTE une ligne à la fin, sans rien effacer
cat salut.txt                      # affiche le contenu :
# → Bonjour
# → Ça va ?

Quand utiliser > ou >> ?

SymboleEffetÀ utiliser pour…
> (une flèche)Remplace tout le contenuRepartir de zéro
>> (deux flèches)Ajoute à la finCompléter un fichier ligne par ligne

Moyen mnémotechnique : deux flèches, deux fois plus de lignes.

Pour écrire beaucoup de texte, le terminal n'est pas pratique : on ouvre le fichier dans un éditeur avec code nom-du-fichier (VS Code, leçon 0.4). echo sert pour une ou deux lignes rapides.

Erreurs fréquentes

  • Utiliser > trois fois de suite : à la fin, il ne reste que la dernière ligne, car chaque > efface la précédente.
  • Oublier l'extension : echo "x" > commandes crée un fichier « commandes », différent de « commandes.txt ».

Notion 6 — Renommer et supprimer : mv, rmdir, rm

Comment l'écrire

mv ancien-nom nouveau-nom          # renomme un fichier OU un dossier (mv = move, déplacer)
mv notes.txt exercices/            # déplace notes.txt dans le dossier exercices
rmdir dossier-vide                 # supprime un dossier, SEULEMENT s'il est vide (donc sans risque)
rm fichier.txt                     # supprime un fichier DÉFINITIVEMENT

Quand utiliser quoi ?

  • Une faute dans un nom ? → mv. Renommer = déplacer vers un nouveau nom.
  • Un dossier vide en trop ? → rmdir.
  • Un fichier inutile ? → rm, mais avec prudence.

⚠️ rm ne passe pas par la corbeille. Le fichier disparaît pour de bon. Avant d'appuyer sur Entrée, relis le nom. N'utilise jamais rm -rf (suppression forcée de tout un dossier) sans être absolument sûr de toi.

Erreurs fréquentes

  • rmdir: failed to remove '…': Directory not empty → le dossier contient encore quelque chose. Regarde avec ls.

Tape cd Docu puis Tab : le terminal complète Documents/. Continue avec form + Tab.

Exercice 2 — Construire avec des commandes

Ce qu'on attend de toi : à la fin, ce fichier existe :

formation-ia/exercices/module-0-1/commandes.txt

Il contient 3 lignes : les 3 commandes que tu trouves les plus utiles, une par ligne. Tout est fait sans la souris.

  1. Place-toi dans formation-ia.
  2. Crée le dossier module-0-1 dans exercices.
  3. Entre dans ce dossier.
  4. Écris tes 3 commandes dans commandes.txt, une ligne à la fois.
  5. Affiche le fichier pour vérifier.

Comment vérifier que c'est réussi : cat commandes.txt affiche exactement 3 lignes, et ls -la montre commandes.txt sur une ligne qui commence par - (un fichier, pas un dossier).

Indice 1

Il te faut, dans l'ordre : cd, mkdir, cd, trois fois echo … >>, puis cat.

Indice 2

Avec >>, le fichier est créé tout seul à la première ligne : pas besoin de touch avant. Vérifie le nom du dossier caractère par caractère : module-0-1.

Correction (ouvre-la après avoir essayé) 
cd ~/Documents/formation-ia          # 1. on se place dans le projet (chemin absolu, marche d'où qu'on soit)
mkdir exercices/module-0-1           # 2. on crée le dossier dans "exercices"
cd exercices/module-0-1              # 3. on entre dedans
echo "pwd" >> commandes.txt          # 4. première ligne (le fichier est créé)
echo "cd" >> commandes.txt           #    deuxième ligne, ajoutée à la fin
echo "ls" >> commandes.txt           #    troisième ligne
cat commandes.txt                    # 5. vérification
# → pwd
# → cd
# → ls

Pourquoi >> et pas > ? Avec >, chaque ligne effacerait la précédente, et il n'en resterait qu'une.

Tu t'es trompé de nom de dossier ? Corrige avec mv exercices/mauvais-nom exercices/module-0-1.

Exercice 3 — Ranger et réparer

Ce qu'on attend de toi : t'entraîner à renommer et supprimer sans risque. À la fin, le dossier exercices/module-0-1/brouillon a été créé, renommé en archive, puis supprimé.

  1. Dans exercices/module-0-1, crée un dossier brouillon.
  2. Renomme-le en archive. Vérifie avec ls.
  3. Supprime-le avec la commande qui ne supprime que les dossiers vides.

Comment vérifier que c'est réussi : ls n'affiche plus que commandes.txt.

Indice

Relis la notion 6 : mv pour renommer, rmdir pour supprimer un dossier vide.

Correction (ouvre-la après avoir essayé) 
mkdir brouillon          # 1. création
mv brouillon archive     # 2. renommage : "déplacer" brouillon vers le nom archive
ls                       # → archive  commandes.txt
rmdir archive            # 3. suppression (il est vide, donc sans danger)
ls                       # → commandes.txt ✅

Questions pour vérifier que tu as compris

1. Tu tapes echo "ls" > test.txt trois fois de suite, avec trois commandes différentes. Combien de lignes contient le fichier à la fin ?

Réponse

Une seule : la dernière. Chaque > écrase le fichier. Pour ajouter, il faut >>.

2. Tu tapes touch et tu obtiens « 'touch' n'est pas reconnu… ». Que se passe-t-il ?

Réponse

Tu es dans l'Invite de commandes (cmd) de Windows, pas dans Git Bash. L'invite commence par C:\ au lieu de finir par $. Ouvre Git Bash.

3. Tu es dans ~/Documents/formation-ia/site/lecons. Quelle commande te ramène dans formation-ia en une seule fois ?

Réponse

cd ../.. : on remonte deux fois (lecons → site → formation-ia). Ou, avec un chemin absolu : cd ~/Documents/formation-ia.
