Projet 1.11 · environ 3 h · GitHub

Mise en ligne avec GitHub Pages et portfolio

Objectif : publier ton site sur Internet, gratuitement, avec une vraie adresse que tu peux envoyer à n'importe qui. Ranger ton dépôt avec un .gitignore et un bon README, et transformer la page Portfolio en vitrine. C'est le livrable de la Phase 1.

Notion 1 — Comment un site arrive sur Internet

Jusqu'ici, ton site existe sur ton PC (fichiers) et sur GitHub (code). Pour qu'un visiteur l'ouvre, il faut un hébergeur : un ordinateur allumé en permanence qui envoie tes fichiers à qui les demande. GitHub Pages le fait gratuitement pour les sites « statiques » (HTML, CSS, JavaScript, sans serveur), exactement comme le tien.

ÉtapeOù
Tu modifies, tu commits, tu git pushton PC → GitHub
GitHub Pages republie automatiquementGitHub → Internet (environ 1 minute)
Le visiteur ouvre https://ton-pseudo.github.io/formation-ia/Internet → son navigateur

En Phase 3, tu passeras à Vercel, qui fait la même chose pour les applications Next.js.

Notion 2 — Le petit problème du dossier site/

GitHub Pages publie soit la racine du dépôt, soit un dossier /docs. Ton site est dans site/. La solution la plus simple : une page index.html à la racine qui redirige vers site/.

<!DOCTYPE html>
<html lang="fr">
  <head>
    <meta charset="UTF-8">
    <meta http-equiv="refresh" content="0; url=site/">   <!-- après 0 seconde, va vers site/ -->
    <title>Formation IA</title>
  </head>
  <body>
    <p><a href="site/">Accéder à la formation</a></p>      <!-- au cas où la redirection est bloquée -->
  </body>
</html>

Notion 3 — Les pièges de la mise en ligne

  • Les majuscules comptent en ligne : sur Windows, Logo.PNG et logo.png sont le même fichier ; sur le serveur, non. Image ou page introuvable en ligne mais pas sur ton PC ? Vérifie la casse.
  • Les chemins absolus comme C:\Users\… ou /site/index.html ne marchent pas en ligne. Toujours des chemins relatifs (css/style.css, ../index.html).
  • Tout est public : le code et ton journal journal.md sont lisibles par tous. Rien de privé, jamais de mot de passe ni de clé.
  • localStorage est par navigateur et par adresse : ta progression cochée en local (localhost ou fichier) ne se retrouve pas sur la version en ligne. Normal : c'est une autre « adresse ».

Notion 4 — Un dépôt professionnel : .gitignore et README

.gitignore : ce que Git doit ignorer

Un fichier texte à la racine, une règle par ligne. Git ne suivra jamais ces fichiers.

# Fichiers système
.DS_Store
Thumbs.db
desktop.ini

# Réglages d'éditeur
.vscode/

# Secrets (Phase 4-5 : clés API) — JAMAIS sur GitHub
.env

# Dépendances installées (Phase 3)
node_modules/

Quand ? Dès le début d'un projet. Attention : un fichier déjà commité n'est pas retiré par le .gitignore.

Le README : la vitrine du dépôt

C'est la première chose qu'un visiteur voit sur GitHub. Un bon README dit : ce qu'est le projet, le lien du site en ligne, les technologies, et comment l'ouvrir. Il s'écrit en Markdown : # Titre, **gras**, - liste, [texte](https://lien), ![alt](image.png).

Le projet, étape par étape

Étape 1 — Ranger le dépôt

Ce qu'on attend de toi : un fichier .gitignore à la racine (notion 4), et la page index.html de redirection à la racine (notion 2). Commit et push.

Comment vérifier : en ouvrant le index.html de la racine, tu arrives sur l'accueil de la formation.

Correction (ouvre-la après avoir essayé) 
cd ~/Documents/formation-ia
code .gitignore          # coller les règles de la notion 4, Ctrl+S
code index.html          # coller la page de redirection de la notion 2, Ctrl+S
git add .gitignore index.html
git commit -m "Ajoute le .gitignore et la redirection vers le site pour GitHub Pages"
git push

Le nom .gitignore commence par un point : c'est un fichier « caché ». ls -la l'affiche.

Étape 2 — Activer GitHub Pages

Ce qu'on attend de toi : ton site accessible à l'adresse https://ton-pseudo.github.io/formation-ia/.

  1. Sur github.com, ouvre ton dépôt formation-ia › onglet Settings.
  2. Dans le menu de gauche : Pages.
  3. Source : Deploy from a branch. Branch : main, dossier / (root). Clique sur Save.
  4. Attends 1 à 2 minutes et rafraîchis : GitHub affiche « Your site is live at … ». Clique sur l'adresse.

Comment vérifier : l'adresse s'ouvre sur ton téléphone, en 4G (sans le wifi de ton PC) : ton site est vraiment sur Internet. Navigue dans toutes les pages et vérifie qu'aucune image ni aucun lien n'est cassé.

Ça ne marche pas ?
  • Erreur 404 : attends encore 2 minutes ; vérifie que l'index.html de redirection est bien poussé à la racine (visible sur la page du dépôt).
  • Le dépôt doit être public (leçon 0.3).
  • Onglet Actions du dépôt : la publication y apparaît (rond orange = en cours, coche verte = publié, croix rouge = erreur).

Questions pour vérifier que tu as compris

1. Une image s'affiche sur ton PC mais pas en ligne. Première chose à vérifier ?

Réponse

Les majuscules du nom de fichier et du src (le serveur les distingue), puis que l'image a bien été commitée et poussée.

2. Tu modifies ton site. Que faut-il faire pour que la version en ligne change ?

Réponse

Commit, puis git push. GitHub Pages republie tout seul en environ une minute.

3. Pourquoi .env dans le .gitignore ?

Réponse

Ce fichier contiendra tes clés secrètes (API) : il ne doit jamais être publié sur GitHub, où des robots cherchent les clés oubliées.

Checklist

  • Mon site est en ligne et fonctionne sur téléphone.
  • Mon dépôt a un .gitignore et un README avec le lien du site.
  • Je connais les pièges : majuscules, chemins, données publiques.
  • Mon portfolio présente chaque projet avec le problème résolu, les technologies et les liens.
