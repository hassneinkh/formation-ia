Git : ton premier historique

Objectif : transformer ton dossier formation-ia en dépôt Git, savoir lire ce que Git te dit, faire des commits avec de bons messages, et relire ton historique.

Notion 1 — C'est quoi, Git ?

L'image à retenir

Pense à un jeu vidéo avec des points de sauvegarde. À chaque étape importante, tu sauvegardes. Si tu fais une bêtise, tu reviens au dernier point. Git fait ça pour ton code.

Le vocabulaire

MotSens
Dépôt (repository, « repo »)Un dossier suivi par Git. Ici : formation-ia.
CommitUn point de sauvegarde : une photo de tes fichiers à un instant, avec un message.
HistoriqueLa liste de tous les commits, du plus récent au plus ancien.
BrancheUne ligne d'historique. La principale s'appelle main (on verra les autres en Phase 2).

Git ou GitHub ?

GitGitHub
C'est…un logiciel sur ton ordinateurun site web
Il sert à…garder l'historiquegarder une copie dans le cloud et la partager
On le voit dans…cette leçonla leçon 0.3

Quand faire un commit ?

  • ✅ Quand tu as terminé une petite étape qui fonctionne : un exercice, une section de page, une correction.
  • ✅ Avant d'essayer quelque chose de risqué : tu pourras revenir en arrière.
  • ❌ Pas à chaque ligne tapée, ni une seule fois par semaine. La bonne taille : une idée = un commit.

Notion 2 — Te présenter à Git : git config

C'est quoi ?

Chaque commit porte le nom et l'email de son auteur. Tu les donnes à Git une seule fois sur ton ordinateur.

Comment l'écrire

git config --global user.name "Ton Prénom Nom"         # ton nom, entre guillemets
git config --global user.email "ton-email@exemple.com" # ton email
git config --global init.defaultBranch main            # la branche principale s'appellera "main"
git config --global --list                             # vérifie : affiche tous tes réglages

--global veut dire « pour tous mes projets sur cet ordinateur ».

Ton email devient visible dans l'historique public de tes projets. Dans la leçon 0.3, tu le remplaceras par l'adresse privée que GitHub te donne.

Notion 3 — Créer le dépôt : git init

C'est quoi ?

git init dit à Git : « à partir de maintenant, suis ce dossier ». Il crée un dossier caché .git qui contient tout l'historique. Ne touche jamais à ce dossier à la main.

Comment l'écrire

cd ~/Documents/formation-ia    # 1. se placer DANS le dossier du projet
git init                       # 2. créer le dépôt
# → Initialized empty Git repository in C:/Users/hsnyt/Documents/formation-ia/.git/

Quand l'utiliser ?

  • ✅ Une seule fois par projet, au tout début, dans le dossier racine du projet.
  • ❌ Jamais dans ta maison (~) ni dans Documents : Git suivrait tout ton ordinateur.
  • ❌ Jamais une deuxième fois dans le même projet.

Erreurs fréquentes

  • fatal: not a git repository → tu n'es pas dans le dossier du projet, ou tu n'as pas encore fait git init. Vérifie avec pwd.

Notion 4 — Les 3 zones et git status

C'est quoi ?

C'est LE concept de Git. Un fichier passe par 3 zones, comme des courses :

ZoneComme…Pour y aller
1. Dossier de travailles articles dans les rayons : tu les modifies librementtu modifies un fichier
2. Panier (staging)le chariot : ce que tu as choisi d'achetergit add
3. Historiquele ticket de caisse : enregistré pour toujoursgit commit

Pourquoi un panier ? Pour choisir précisément quoi sauvegarder ensemble. Si tu as modifié 3 fichiers mais que seulement 2 vont ensemble, tu mets ces 2 dans le panier et tu fais un commit, puis le 3e dans un autre commit.

Comment lire git status

git status te dit dans quelle zone est chaque fichier. C'est ta boussole : tape-le avant et après chaque commande Git.

Git affiche…Ça veut dire…Prochaine action
Untracked files (en rouge)Fichier nouveau, que Git ne suit pas encoregit add
Changes not staged for commit (en rouge)Fichier suivi, modifié, mais pas dans le paniergit add
Changes to be committed (en vert)Dans le panier, prêtgit commit
nothing to commit, working tree cleanTout est sauvegardéRien : bravo !

Voir le détail : git diff

git diff            # montre les lignes modifiées qui ne sont PAS encore dans le panier
git diff --staged   # montre ce qui EST dans le panier

Les lignes qui commencent par + (vert) sont ajoutées, celles avec - (rouge) sont supprimées. Appuie sur q pour quitter l'affichage.

Notion 5 — Remplir le panier : git add

Comment l'écrire

git add journal.md         # ajoute UN fichier précis au panier
git add site/css/style.css journal.md   # plusieurs fichiers, séparés par un espace
git add .                  # ajoute TOUT ce qui a changé dans le dossier actuel (le point = « ici »)

Quand utiliser lequel ?

  • git add nom-du-fichier → quand tu veux contrôler exactement ce qui part dans le commit. C'est la bonne habitude.
  • git add . → quand tu es sûr que tous les changements vont ensemble. Fais toujours git status avant, pour voir ce que tu ajoutes.

Retirer un fichier du panier

git restore --staged journal.md   # le fichier sort du panier ; tes modifications sont conservées

Notion 6 — Sauvegarder : git commit et un bon message

Comment l'écrire

git commit -m "Ajoute mon entrée de journal pour la leçon 0.2"
#           ↑ -m = message, toujours entre guillemets

Un bon message

La règle : quelqu'un qui lit seulement le message comprend ce qui a changé. Commence par un verbe d'action au présent : Ajoute, Corrige, Modifie, Supprime, Renomme.

❌ MauvaisPourquoi✅ Bon
modifModif de quoi ?Change la couleur d'accent du site en rouge
premier commit : base« Base » de quoi ?Premier commit : base du site de formation
je comprend comment git addDécrit ton ressenti, pas le changementAjoute l'exercice 2 de la leçon 0.2

Erreurs fréquentes

  • Tu as oublié -m et un éditeur bizarre (Vim) s'ouvre en plein terminal. Pour en sortir sans paniquer : appuie sur Échap, tape :q! puis Entrée. Le commit est annulé : recommence avec -m "…".
  • nothing added to commit → ton panier est vide. Tu as oublié git add.
  • warning: LF will be replaced by CRLF → ce n'est pas une erreur. Windows et Mac/Linux n'écrivent pas les fins de ligne pareil, et Git s'en occupe. Tu peux ignorer ce message.

Notion 7 — Relire l'historique : git log

Comment l'écrire

git log --oneline
# → 7063c77 Update README.md
# → 1d28fe5 Ajoute l'exercice 2 de la leçon 0.2
# → 4ec4e38 Premier commit : base du site de formation

Chaque ligne = un commit. Le code au début (7063c77) est son identifiant unique. Le plus récent est en haut. Si la liste est longue, appuie sur q pour quitter.

Le cycle que tu feras des centaines de fois :

git status → git add fichier → git status → git commit -m "Verbe + ce qui a changé" → git log --oneline

Exercice 2 — Le cycle complet avec ton journal

Ce qu'on attend de toi : une nouvelle entrée dans journal.md, enregistrée dans un nouveau commit qui ne contient que ce fichier.

  1. Ouvre le journal : code journal.md. Sous la ligne -->, écris ton entrée sur la leçon 0.2 avec le modèle (date, leçon, 3 questions). Enregistre (Ctrl+S).
  2. Tape git status. Dans quelle zone est journal.md ?
  3. Tape git diff pour voir tes lignes ajoutées, puis q.
  4. Mets seulement journal.md dans le panier, puis fais le commit.
  5. Vérifie avec git log --oneline.

Comment vérifier que c'est réussi : git log --oneline affiche un commit de plus, et git show --stat (le détail du dernier commit) ne liste que journal.md.

Indice

À l'étape 2, cherche la phrase Changes not staged for commit dans le tableau de la notion 4. À l'étape 4, utilise git add avec le nom du fichier, pas le point.

Les commandes :

Questions pour vérifier que tu as compris

1. Tu viens de modifier journal.md et tu l'as enregistré. Dans quelle zone est-il ? Et après git add journal.md ?

Réponse

D'abord dans la zone 1, le dossier de travail (en rouge dans git status). Après git add, dans la zone 2, le panier (en vert). Il ira dans l'historique au git commit.

2. Tu tapes git commit -m "Corrige le menu" et Git répond nothing added to commit. Pourquoi ?

Réponse

Le panier est vide : tu as oublié git add. Fais git status, ajoute le fichier, puis recommence le commit.

3. Lequel de ces messages est le meilleur, et pourquoi ? update · Corrige la faute dans le titre de l'accueil · j'ai fait des trucs

Réponse

Corrige la faute dans le titre de l'accueil : il commence par un verbe d'action et dit précisément quoi et où.
