Git : ton premier historique

Objectif : transformer ton dossier formation-ia en dépôt Git, faire tes premiers commits et savoir lire l'historique.

C'est quoi, Git ?

Imagine un jeu vidéo avec des points de sauvegarde. À chaque étape importante, tu sauvegardes. Si tu fais une bêtise, tu reviens au dernier point. Git, c'est ça pour ton code.

  • Chaque point de sauvegarde s'appelle un commit.
  • Chaque commit a un message qui explique ce qui a changé.
  • L'ensemble des commits forme l'historique du projet.
  • Un dossier suivi par Git s'appelle un dépôt (en anglais, repository ou repo).

Git ≠ GitHub. Git est le logiciel qui garde l'historique sur ton ordinateur. GitHub est un site web qui garde une copie de tes dépôts dans le cloud (leçon 0.3).

Les 3 zones de Git

C'est LE concept à comprendre. Un fichier passe par trois étapes :

ZoneCe que c'estCommande pour y aller
1. Dossier de travailTes fichiers, tels que tu les modifies(tu modifies un fichier)
2. Zone de préparation (staging)Le « panier » de ce que tu veux sauvegardergit add
3. HistoriqueLes commits enregistrés pour toujoursgit commit

Pourquoi un panier ? Pour choisir précisément quoi sauvegarder ensemble, comme quand tu ranges tes courses par rayon.

Étape 1 — Te présenter à Git (une seule fois)

Chaque commit porte le nom de son auteur. Dans Git Bash, avec tes informations :

git config --global user.name "Ton Prénom Nom"
git config --global user.email "ton-email@exemple.com"
git config --global init.defaultBranch main
# Vérifier :
git config --global --list

Ton email devient visible dans l'historique public de tes projets. Dans la leçon 0.3, on le remplacera par l'adresse « privée » que GitHub te donne.

Étape 2 — Créer le dépôt

cd ~/Documents/formation-ia
git init          # crée un dépôt vide (un dossier caché .git)
git status        # montre l'état : quels fichiers sont nouveaux ou modifiés

git status affiche tes fichiers en rouge : Git les voit, mais ils ne sont pas encore dans le panier. git status est ta boussole : tape-le tout le temps.

Étape 3 — Ton premier commit

git add .                                  # met TOUS les fichiers dans le panier (le point = « tout »)
git status                                 # ils sont maintenant en vert
git commit -m "Premier commit : base du site de formation"
git log --oneline                          # affiche l'historique, une ligne par commit

Un bon message de commit

❌ Mauvais✅ Bon
modifAjoute la leçon 0.1 dans mon journal
trucsCorrige la couleur des liens du menu
aaaaCrée l'exercice 2 sur les commandes du terminal

La règle : quelqu'un qui lit seulement le message doit comprendre ce qui a changé.

Exercices

Exercice 1 — Le premier commit

Fais les étapes 1, 2 et 3 ci-dessus. À la fin, git log --oneline doit afficher ton commit.

Exercice 2 — Le cycle complet

  1. Ouvre journal.md et ajoute ton entrée sur la leçon 0.2.
  2. Tape git status. Que remarques-tu ?
  3. Tape git diff : il affiche exactement les lignes modifiées (appuie sur q pour quitter).
  4. Mets le fichier dans le panier, puis fais un commit avec un bon message.
  5. Vérifie avec git log --oneline : tu as maintenant 2 commits.
Indice

Pour ajouter un seul fichier au panier : git add journal.md.

Exercice 3 — Explique avec tes mots

Écris dans exercices/module-0-2/git-en-3-phrases.md ce que sont un commit, le panier (staging) et l'historique, comme si tu l'expliquais à un ami. Puis fais un commit. Demande ensuite à Claude de vérifier ton explication.

Checklist

  • Je sais la différence entre Git et GitHub.
  • Je connais les 3 zones : dossier de travail, panier, historique.
  • J'utilise git status, git add, git commit -m, git log --oneline.
  • J'écris des messages de commit clairs.

Journal et commit

C'est fait dans l'exercice 2. Bravo : à partir de maintenant, chaque leçon se termine par un commit.
