Leçon 0.3 · environ 2 h · GitHub

GitHub : ton code dans le cloud

Objectif : créer ton compte GitHub, y envoyer ton dépôt formation-ia, et maîtriser les allers-retours entre ton PC et GitHub (push et pull).

Notion 1 — Pourquoi GitHub ?

C'est quoi ?

GitHub est un site qui garde une copie de tes dépôts Git dans le cloud. Ton PC a l'original, GitHub a la copie, et tu les synchronises.

À quoi ça sert concrètement

  • Sauvegarde : si ton PC tombe en panne, ton code est en sécurité.
  • Vitrine : ton profil GitHub est le CV d'un développeur. Clients et recruteurs le regardent.
  • Travail d'équipe : c'est là que les équipes travaillent ensemble (Phase 3).
  • Mise en ligne : GitHub Pages publie ton site gratuitement (leçon 1.11).

Le vocabulaire

MotSensQuand on l'utilise
remoteLa copie de ton dépôt sur GitHub. Par convention, on l'appelle origin.Une fois, pour relier ton PC à GitHub
git pushEnvoyer tes commits du PC vers GitHub ⬆️Après chaque commit (ou série de commits)
git pullRécupérer sur ton PC les commits qui sont sur GitHub ⬇️Quand quelque chose a changé sur GitHub (une modification faite sur le site, un autre ordinateur…)
git cloneTélécharger un dépôt completSur un nouvel ordinateur, ou pour récupérer le projet de quelqu'un

Notion 2 — Créer et protéger ton compte

Les étapes

  1. Va sur github.com et clique sur Sign up. C'est toi qui crées le compte : Claude ne crée jamais de compte à ta place.
  2. Choisis un pseudo professionnel (par exemple hassnein-khawary). Il apparaîtra dans toutes tes adresses : github.com/ton-pseudo.
  3. Active la double authentification : Settings › Password and authentication › Enable two-factor authentication. Même si on vole ton mot de passe, ton compte reste protégé.

Protéger ton email

Chaque commit contient l'email que tu as configuré dans Git. Sur un dépôt public, tout le monde peut le lire, y compris des robots qui envoient du spam. GitHub te donne une adresse « privée » à la place :

  1. Sur GitHub : Settings › Emails, coche Keep my email addresses private.
  2. Juste en dessous, GitHub affiche une adresse du type 12345678+pseudo@users.noreply.github.com. Copie-la.
  3. Dans Git Bash :
git config --global user.email "12345678+pseudo@users.noreply.github.com"
git config --global user.email     # vérifie : affiche la nouvelle adresse

Les prochains commits utiliseront cette adresse. Les anciens gardent l'ancienne : ce n'est pas grave.

Notion 3 — Créer le dépôt sur GitHub

Les étapes

  1. Clique sur le + en haut à droite, puis New repository.
  2. Repository name : formation-ia (le même nom que ton dossier, c'est plus clair).
  3. Visibilité : Public. GitHub Pages gratuit en a besoin, et ça montre ton travail. ⚠️ Tout ce que tu y mets est lisible par tous, y compris ton journal : n'y écris rien de trop personnel.
  4. Ne coche rien d'autre : pas de README, pas de .gitignore, pas de licence. Ton dépôt local a déjà ses fichiers, et un README créé ici entrerait en conflit.
  5. Clique sur Create repository. GitHub affiche une page avec des commandes : c'est la notion 4.

Quand choisir « Private » ?

Pour un projet client confidentiel, ou du code avec des informations sensibles. Pour ta formation et ton portfolio : Public.

Notion 4 — Relier ton PC à GitHub et envoyer : remote et push

Comment l'écrire

cd ~/Documents/formation-ia
git remote add origin https://github.com/TON-PSEUDO/formation-ia.git
#          ↑ ajoute  ↑ le nom  ↑ l'adresse de ton dépôt (copie-la depuis la page GitHub)
git remote -v              # vérifie : affiche origin et l'adresse (2 lignes, fetch et push)
git push -u origin main    # premier envoi de la branche main vers origin
#        ↑ -u retient « origin main » : les prochaines fois, un simple git push suffit

La connexion

Au premier push, une fenêtre s'ouvre pour te connecter à GitHub dans le navigateur. C'est normal : c'est Git Credential Manager, installé avec Git. Clique sur Sign in with your browser et connecte-toi toi-même. Ton ordinateur s'en souviendra ensuite.

Quand l'utiliser ?

  • git remote add → une seule fois par projet.
  • git push -u origin main → le premier envoi.
  • git push → après chaque commit, pour que GitHub soit à jour.

Erreurs fréquentes

  • error: remote origin already exists → tu as déjà fait git remote add. Pas besoin de recommencer. Vérifie avec git remote -v.
  • ! [rejected] main -> main (fetch first) → GitHub a des commits que ton PC n'a pas (par exemple une modification faite sur le site). Fais d'abord git pull, puis git push.
  • Repository not found → l'adresse est fausse (faute dans le pseudo ou le nom du dépôt). Corrige-la avec git remote set-url origin https://github.com/BON-PSEUDO/formation-ia.git.

Notion 5 — Récupérer : git pull

C'est quoi ?

git pull télécharge les commits de GitHub que ton PC n'a pas encore, et les ajoute à ton historique local.

Quand l'utiliser ?

  • Tu as modifié un fichier directement sur github.com (avec le crayon ✏️).
  • Tu travailles sur deux ordinateurs : commence toujours par git pull en t'asseyant.
  • Git refuse ton push avec fetch first.

Si un éditeur s'ouvre pendant le pull

Parfois Git ouvre Vim pour un message de « merge » (fusion). Garde le message proposé : appuie sur Échap, tape :wq puis Entrée.

Le rythme de travail d'un développeur :

git pull (en commençant) → modifier → git add → git commit -m "…" → git push

Exercices

Exercice 1 — Ton premier push

Ce qu'on attend de toi : ton dépôt formation-ia est visible sur github.com/ton-pseudo/formation-ia, avec tous tes fichiers et tes commits.

  1. Crée et protège ton compte (notion 2).
  2. Crée le dépôt vide sur GitHub (notion 3).
  3. Relie ton PC et envoie (notion 4).
  4. Rafraîchis la page du dépôt sur GitHub.

Comment vérifier que c'est réussi : sur GitHub, tu vois la liste de tes fichiers, ton README.md affiché en dessous, et le nombre de commits en haut à droite de la liste. Dans Git Bash, git status dit Your branch is up to date with 'origin/main'.

Indice

L'adresse de ton dépôt est affichée sur la page GitHub juste après sa création, dans la case « Quick setup ». Copie-la avec le bouton 📋.

Correction (ouvre-la après avoir essayé) 
cd ~/Documents/formation-ia
git remote add origin https://github.com/hassnein-khawary/formation-ia.git   # avec TON pseudo
git remote -v
# → origin  https://github.com/hassnein-khawary/formation-ia.git (fetch)
# → origin  https://github.com/hassnein-khawary/formation-ia.git (push)
git push -u origin main
# (fenêtre de connexion → Sign in with your browser)
# → branch 'main' set up to track 'origin/main'. ✅

Exercice 2 — L'aller-retour

Ce qu'on attend de toi : une modification faite sur GitHub, récupérée sur ton PC. À la fin, ton README.md local contient une ligne « Mon profil GitHub : https://github.com/ton-pseudo », et git log --oneline montre le commit fait sur GitHub.

  1. Sur github.com, ouvre README.md et clique sur le crayon ✏️ (Edit this file).
  2. Sous le titre, ajoute la ligne Mon profil GitHub : https://github.com/ton-pseudo (avec ton vrai pseudo).
  3. Clique sur Commit changes…, écris un bon message, puis valide.
  4. Sur ton PC, récupère ce changement.
  5. Vérifie avec git log --oneline et en ouvrant README.md.

Comment vérifier que c'est réussi : le commit fait sur GitHub apparaît en haut de git log --oneline sur ton PC.

Indice

Envoyer, c'est push. Récupérer, c'est le contraire (notion 5).

Correction (ouvre-la après avoir essayé)

Sur GitHub, message du commit : Ajoute le lien vers mon profil GitHub dans le README (plutôt que le message automatique « Update README.md », qui ne dit pas ce qui a changé).

git pull                # ⬇️ récupère le commit fait sur GitHub
git log --oneline       # il est en haut de la liste ✅
cat README.md           # la ligne "Mon profil GitHub : …" est là

Exercice 3 — Explorer un commit sur GitHub

Ce qu'on attend de toi : savoir retrouver ce qui a changé dans un commit, sur le site GitHub. Rien à créer.

  1. Sur la page de ton dépôt, clique sur le lien Commits (icône d'horloge 🕐, au-dessus de la liste des fichiers).
  2. Ouvre ton commit du journal (leçon 0.2).
  3. Repère les lignes en vert (ajoutées) et en rouge (supprimées).

Comment vérifier que c'est réussi : tu peux dire, sans ouvrir le fichier, quelles lignes tu as ajoutées dans ce commit.

Ce qu'il faut remarquer

C'est exactement ce qu'affiche git diff dans le terminal, mais en plus lisible. Plus tard, quand quelqu'un relira ton code (une Pull Request, Phase 3), c'est cette vue qu'il utilisera.

Questions pour vérifier que tu as compris

1. Tu as fait un commit sur ton PC. Est-il déjà sur GitHub ?

Réponse

Non. Un commit reste sur ton PC tant que tu n'as pas fait git push.

2. Ton git push est refusé avec fetch first. Que fais-tu ?

Réponse

GitHub a des commits que ton PC n'a pas. Tu fais git pull pour les récupérer, puis git push.

3. Pourquoi utiliser l'adresse …@users.noreply.github.com dans Git ?

Réponse

Parce que l'email de chaque commit est visible par tous sur un dépôt public. L'adresse « noreply » protège ta vraie adresse du spam.

Checklist

  • J'ai un compte GitHub avec la double authentification.
  • Mon email est protégé.
  • Mon dépôt formation-ia est sur GitHub.
  • Je sais quand utiliser git push et git pull.
  • Je sais réagir aux erreurs fetch first et remote origin already exists.

Journal et commit

Ajoute ton entrée dans journal.md, puis : git add journal.md → git commit -m "…" → git push.
