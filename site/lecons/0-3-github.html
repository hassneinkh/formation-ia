GitHub : ton code dans le cloud

Objectif : créer ton compte GitHub, y envoyer ton dépôt formation-ia et comprendre les allers-retours entre ton PC et GitHub.

Pourquoi GitHub ?

  • Sauvegarde : si ton PC tombe en panne, ton code est en sécurité.
  • Vitrine : ton profil GitHub est le CV d'un développeur. Les clients et les recruteurs le regardent.
  • Collaboration : c'est là que les équipes travaillent ensemble (Phase 3).
  • Mise en ligne : GitHub Pages publie ton site gratuitement (leçon 1.11).

Le vocabulaire

MotSens
remoteLa copie de ton dépôt sur GitHub. On l'appelle par convention origin.
git pushEnvoyer tes commits de ton PC vers GitHub.
git pullRécupérer sur ton PC les commits qui sont sur GitHub.
git cloneTélécharger un dépôt GitHub complet sur un ordinateur.

Étape 1 — Créer ton compte

  1. Va sur github.com et crée un compte. C'est toi qui le fais : Claude ne crée jamais de compte à ta place.
  2. Choisis un pseudo professionnel (par exemple ton prénom et ton nom) : il apparaîtra dans tes URL.
  3. Active la double authentification (Settings › Password and authentication).

Étape 2 — Protéger ton email

  1. Sur GitHub : Settings › Emails, coche Keep my email addresses private.
  2. GitHub t'affiche une adresse du type 12345678+pseudo@users.noreply.github.com.
  3. Utilise-la dans Git :
git config --global user.email "12345678+pseudo@users.noreply.github.com"

Étape 3 — Créer le dépôt sur GitHub

  1. Clique sur + en haut à droite, puis New repository.
  2. Nom : formation-ia.
  3. Visibilité : Public. GitHub Pages gratuit en a besoin, et ça montre ton travail. (Ton journal sera donc lisible : n'y mets rien de trop personnel.)
  4. Ne coche rien d'autre (pas de README, pas de .gitignore) : ton dépôt local en a déjà un.
  5. Clique sur Create repository.

Étape 4 — Relier ton PC à GitHub et envoyer

cd ~/Documents/formation-ia
git remote add origin https://github.com/TON-PSEUDO/formation-ia.git
git remote -v                # vérifie que le lien est bien enregistré
git push -u origin main      # premier envoi ; -u retient le chemin pour les prochaines fois

Une fenêtre s'ouvre pour te connecter à GitHub dans le navigateur. C'est normal : c'est Git Credential Manager, installé avec Git. Connecte-toi toi-même. Rafraîchis ensuite la page de ton dépôt : tes fichiers y sont !

Pour toutes les fois suivantes, un simple git push suffit.

Le rythme de travail d'un développeur :

modifier → git add → git commit -m "…" → git push

Exercices

Exercice 1 — Premier push

Fais les étapes 1 à 4. Vérifie sur github.com que tu vois ton README.md affiché sous la liste des fichiers.

Exercice 2 — L'aller-retour

  1. Sur github.com, ouvre README.md, clique sur le crayon ✏️ et ajoute une ligne « Mon profil GitHub : … ». Valide avec Commit changes.
  2. Sur ton PC, ce changement n'existe pas encore. Récupère-le avec la bonne commande.
  3. Vérifie avec git log --oneline et en ouvrant le fichier.
Indice

Envoyer, c'est push. Récupérer, c'est…

Exercice 3 — Explorer GitHub

Sur ton dépôt, clique sur l'onglet Commits (l'horloge 🕐). Ouvre un commit : GitHub montre en vert les lignes ajoutées et en rouge les lignes supprimées. C'est la même chose que git diff.

Checklist

  • J'ai un compte GitHub avec la double authentification.
  • Mon email est protégé.
  • Mon dépôt formation-ia est sur GitHub.
  • Je sais faire git push et git pull, et je comprends la différence.

Journal et commit

Ajoute ton entrée dans journal.md, puis : add → commit → push.
